Projets

Deux plateformes construites de zéro

Plateforme Microsoft Fabric de bout en bout

Fabric · PySpark · T-SQL
  • Source SQL Server locale (données CRM et ERP) exposée via une passerelle on-premise, capacité F2 et espace de travail dédié.
  • Ingestion par pipeline Data Factory ForEach dynamique piloté par une table de configuration : ajouter une source revient à ajouter une ligne. Second pipeline pour les CSV récurrents d'un dossier partagé.
  • Silver en PySpark (déduplication par ROW_NUMBER sur fenêtrage, typage, normalisation, contrôles qualité avec exceptions bloquantes sur seuils), puis bascule en T-SQL dans un Warehouse pour rendre la maintenance accessible à une équipe sans Python — architecture hybride Lakehouse + Warehouse.
  • Gold en schéma en étoile : clés de substitution persistées, dimension client en SCD 1, dimension produit en SCD 2, dimension Date générée, membres inconnus, chargements idempotents par procédures stockées.
  • Restitution en modèle sémantique Direct Lake, intégration Git Azure DevOps avec déploiements DEV → TEST → PROD, gouvernance par lineage Purview, étiquettes de confidentialité et sécurité au niveau des lignes.
  • Data Factory
  • Delta Lake
  • Direct Lake
  • Azure DevOps
  • Purview

Pipeline analytique Snowflake + dbt

Snowflake · dbt · GitHub Actions
  • Fondations séparées RAW et ANALYTICS, warehouse dimensionné au plus juste et rôles distincts.
  • Chargement par PUT en SnowSQL vers un stage interne puis COPY INTO dans RAW, avec la logique de chargement encapsulée dans des procédures stockées.
  • Couche staging dbt en 1:1 par source (typage, renommage, nettoyage, déduplication, aucune règle métier), puis marts en schéma en étoile où les règles métier ne sont écrites qu'une seule fois.
  • 17 tests YAML (unique, not_null, relationships, accepted_values), documentation et lineage générés depuis le code.
  • CI/CD par GitHub Actions planifié en cron, rejouant dbt run puis dbt test à chaque exécution.
